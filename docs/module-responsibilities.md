# 模块职责

## 设计原则

每个模块都应有明确边界。系统的安全性和长期可维护性依赖于职责分离：采集模块不解释，事件模块不叙事，状态模块不生成语言，LLM 不读取原始数据。

## Riot Adapter

职责：

- 连接 Riot 实时客户端 API。
- 读取结构化游戏数据。
- 标准化时间、玩家、英雄、装备、等级、生命值、法力值、目标和事件数据。
- 为下游提供带时间戳的数据快照。

输入：

- Riot Live Client Data API 响应。

输出：

- 标准化 API 数据快照。

禁止职责：

- 不判断事件重要性。
- 不生成自然语言。
- 不绕过 Visibility Filter 直接把数据交给 LLM。

主要风险：

- API 数据不完整或延迟。
- 数据结构随客户端版本变化。
- 某些数据虽然来自 API，但仍需确认是否适合进入解说链路。

## OBS Vision Adapter

职责：

- 接收 OBS 捕获的玩家本人游戏画面。
- 识别画面中实际可见的信息，例如小地图动向、技能动画、英雄移动、镜头位置和视觉特效。
- 为视觉识别结果附带置信度、时间戳和来源区域。

输入：

- OBS 屏幕捕获帧。

输出：

- 标准化视觉观察结果。

禁止职责：

- 不根据不可见区域推断敌人位置。
- 不预测未来事件。
- 不把低置信结果标记为确定事实。
- 不直接驱动解说输出。

主要风险：

- 小地图识别受分辨率、UI 缩放、皮肤、特效和直播压缩影响。
- 技能动画可能被误识别。
- 玩家镜头快速移动会导致视觉信息过期。

## Visibility Filter

职责：

- 作为所有输入进入核心系统前的安全边界。
- 过滤或降级不允许进入解说链路的信息。
- 标记每条事实的可见性来源和置信度。
- 阻止后续模块访问未经治理的原始数据。

输入：

- Riot Adapter 数据。
- OBS Vision Adapter 视觉结果。

输出：

- 合法可见、带来源标记的事实数据。

禁止职责：

- 不解释事件意义。
- 不生成解说。
- 不为了增强效果保留隐藏信息。

主要风险：

- 可见性规则不完整会导致信息泄露。
- API 数据与玩家画面可见性之间可能存在语义差异。
- 后续模块如果绕过该模块，会破坏整个安全边界。

## State Fusion

职责：

- 将 API 数据与 OBS 可见信息合并为统一比赛快照。
- 处理时间对齐、来源冲突、置信度合并和状态过期。
- 为 Event Detection 和 Game State Engine 提供一致的事实基础。

输入：

- Visibility Filter 输出的合法可见事实。

输出：

- 当前比赛状态快照。
- 状态变更记录。

禁止职责：

- 不判断事件是否值得解说。
- 不生成自然语言。
- 不把未确认视觉信息提升为确定事实。

主要风险：

- API 与视觉输入延迟不同。
- 同一事件可能从两个来源重复出现。
- 状态过期处理不当会产生错误解说。

## Event Detection

职责：

- 从状态变化中识别已经发生的事实事件。
- 描述事件的类型、参与者、时间、位置和结果。
- 输出可供 Game State Engine 解释的事件对象。

输入：

- State Fusion 输出的比赛状态快照和状态变更。

输出：

- 结构化事件，例如击杀、资源获取、团战开始、团战结束、一打一、防御塔变化。

禁止职责：

- 不解释事件重要性。
- 不决定是否发言。
- 不选择解说语气。
- 不生成自然语言。

主要风险：

- 事件边界难以判断，例如团战何时开始或结束。
- 多个事件可能重叠。
- 视觉和 API 事件时间不一致。

## Game State Engine

职责：

- 解释事件在当前比赛背景中的含义。
- 维护比赛阶段、资源状态、经济趋势、死亡时间、目标压力和推进机会等上下文。
- 为事件计算重要性和叙事角度。

输入：

- State Fusion 当前状态。
- Event Detection 输出的事实事件。

输出：

- 结构化游戏状态解释。
- 事件重要性。
- 背景摘要。
- 可讲述角度。

禁止职责：

- 不生成自然语言。
- 不直接调用 LLM。
- 不做隐藏信息推断。
- 不提供操作建议。

主要风险：

- 重要性评分过度简化会让解说失真。
- 如果引入过多策略知识，可能滑向 AI 教练。
- 不同分段和比赛节奏下，事件价值不同。

## Narrative Director

职责：

- 决定 AI 是否发言。
- 决定发言优先级。
- 决定情绪强度、解说风格和节奏。
- 在多个候选事件之间选择最值得说的内容。
- 执行沉默策略和过期策略。

输入：

- Game State Engine 输出的结构化解释。
- 最近解说历史。
- 当前 TTS 状态。

输出：

- 叙事决策，例如发言、不发言、延迟发言、替换队列、提高情绪强度。

禁止职责：

- 不生成最终自然语言。
- 不读取原始 API 或原始画面。
- 不引入未确认事实。
- 不把解说变成操作建议。

主要风险：

- 过于频繁发言会干扰玩家。
- 过于保守会失去解说存在感。
- 情绪强度如果只看事件类型，会显得廉价。

## Prompt Builder

职责：

- 将叙事决策和结构化状态解释转换为 LLM 提示词。
- 控制提示词格式、事实白名单、语气限制、禁止输出和长度。
- 确保 LLM 不接触原始游戏状态数据。

输入：

- Narrative Director 的叙事决策。
- Game State Engine 的结构化摘要。
- 解说风格配置。

输出：

- 结构化 LLM 提示词包。

禁止职责：

- 不自行添加事实。
- 不让 LLM 访问未经治理的原始数据。
- 不把策略建议写入提示词。

主要风险：

- 提示词过长导致延迟和成本上升。
- 提示词约束不足导致模型输出建议或预测。
- 事实组织不清会诱发模型幻觉。

## LLM Commentary Generator

职责：

- 根据 Prompt Builder 提供的结构化提示词生成自然语言解说。
- 保持专业电竞解说风格。
- 遵守长度、语气和禁止输出约束。

输入：

- Prompt Builder 输出的结构化提示词包。

输出：

- 一段可交给 TTS 的解说文本。

禁止职责：

- 不读取原始 API 数据。
- 不读取原始 OBS 画面。
- 不自行推断隐藏信息。
- 不输出操作建议。

主要风险：

- 模型幻觉。
- 语言风格像日志播报。
- 过度解释导致玩家分心。

## TTS Output

职责：

- 将解说文本转换为语音。
- 管理播放队列、打断、过期丢弃和音量策略。
- 确保语音输出符合实时体验。

输入：

- LLM Commentary Generator 输出的文本。
- Narrative Director 的优先级和过期策略。

输出：

- 实时语音解说。

禁止职责：

- 不修改事实含义。
- 不自行生成额外内容。
- 不播放已过期或被替换的解说。

主要风险：

- TTS 延迟导致解说错过时机。
- 语音过长覆盖游戏关键音效。
- 多段语音排队导致旧事件被迟到播报。
