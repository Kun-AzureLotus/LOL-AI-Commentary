# Game State Engine

## 目的

Game State Engine 的职责是解释事件的意义。Event Detection 只负责说明“发生了什么”，而 Game State Engine 负责说明“为什么这件事重要”。

它是 AI 解说听起来像专业解说而不是游戏日志播报器的关键模块。

## 输入

Game State Engine 接收两类输入：

- State Fusion 输出的当前比赛状态。
- Event Detection 输出的事实事件。

输入必须已经通过 Visibility Filter。Game State Engine 不允许访问原始 API 响应、原始 OBS 画面或任何未经治理的数据。

## 输出

Game State Engine 输出结构化解释，不输出自然语言。

典型输出包括：

- 事件类型。
- 事件重要性。
- 比赛阶段。
- 资源背景。
- 经济或等级背景。
- 死亡时间影响。
- 推进影响。
- 团战结果影响。
- 可讲述角度。
- 置信度和风险标记。

## 与 Event Detection 的边界

Event Detection 示例：

- 蓝色方击杀红色方 ADC。
- 红色方拿下小龙。
- 中路爆发三人团战。
- 蓝色方推掉中路一塔。

Game State Engine 示例：

- 这次击杀发生在小龙刷新前，因此会影响资源争夺。
- 这条小龙让红色方进入龙魂点。
- 这波团战是二换四，蓝色方有机会转向男爵。
- 中路一塔被推掉后，蓝色方视野和转线空间扩大。

两者必须分离。事件检测如果直接解释意义，会让事实层和判断层耦合；Game State Engine 如果重新判断事件事实，会增加重复和冲突。

## 核心状态维度

### 比赛阶段

系统应根据游戏时间、等级、装备和地图目标判断比赛阶段。

初始阶段可以粗分为：

- 前期：对线和第一批资源争夺。
- 中期：外塔、先锋、小龙和转线节奏。
- 后期：男爵、远古龙、高死亡时间和终局推进。

阶段不是单纯时间判断。20 分钟时如果经济差距极大，比赛可能已经进入终局压力；30 分钟时如果双方仍围绕外塔和小龙周旋，解说方式也应不同。

### 资源状态

Game State Engine 应维护资源上下文：

- 小龙数量。
- 是否接近龙魂。
- 男爵是否已经刷新。
- 远古龙是否存在。
- 峡谷先锋或虚空巢虫等阶段性资源是否相关。
- 防御塔和水晶状态。

资源状态决定事件价值。同样一次击杀，如果发生在男爵刷新后，价值可能远高于一次普通线上击杀。

### 死亡时间

死亡时间会影响事件后果。

前期击杀可能只带来一小波兵线优势。后期核心英雄阵亡则可能导致男爵、防御塔、水晶或比赛结束。

Game State Engine 应关注：

- 阵亡英雄位置和角色。
- 当前游戏时间下的复活时间。
- 阵亡后是否影响附近目标。
- 是否形成明显人数差。

### 经济与等级

经济和等级用于解释力量对比，但不应直接转化为操作建议。

可以表达：

- “这波击杀让蓝色方进一步扩大领先。”
- “虽然红色方拿下资源，但他们付出了两个人头代价。”

不应表达：

- “现在应该立刻开男爵。”
- “你们该撤退。”

### 地图与推进

地图状态决定事件是否能转化为目标。

Game State Engine 应关注：

- 哪些防御塔已掉。
- 哪一路兵线可能带来推进。
- 团战发生位置是否靠近中立资源。
- 某次击杀是否打开地图空间。

该模块只能解释已经发生或基于公开规则确定的后果，不能推断隐藏敌人正在做什么。

## 事件重要性

事件重要性用于帮助 Narrative Director 判断是否发言。

MVP 可以使用分级模型：

- 低：普通消耗、低价值击杀、无后续资源影响。
- 中：线上击杀、防御塔变化、小规模战斗。
- 高：关键资源争夺、多人团战、终结赏金、龙魂点、男爵相关事件。
- 极高：远古龙、男爵后团战、后期核心阵亡、可能直接结束比赛的推进。

重要性不是事件类型固定值。一次击杀是否重要取决于比赛时间、英雄角色、资源状态、地图位置和后续影响。

## 可讲述角度

Game State Engine 不写解说词，但应提供可讲述角度。

例如：

- 资源角度：这波导致小龙争夺权改变。
- 经济角度：领先方扩大优势，落后方止血。
- 节奏角度：一方获得主动权。
- 团战角度：关键技能或核心英雄存活决定结果。
- 终局角度：这波可能打开结束比赛的窗口。

Narrative Director 可以根据这些角度选择是否发言，Prompt Builder 再把选定角度转为提示词。

## 置信度

Game State Engine 必须保留置信度。

API 直接确认的事实通常置信度较高。OBS 视觉识别结果可能受画面质量影响，置信度较低时应降级或不进入关键解说。

低置信信息可以用于内部候选判断，但不能被 LLM 表达为确定事实。

## 禁止事项

Game State Engine 不得：

- 生成自然语言解说。
- 调用 LLM。
- 提供操作建议。
- 推断战争迷雾内敌人位置。
- 预测未来事件。
- 使用未经 Visibility Filter 处理的数据。
- 把策略知识作为玩家指导输出。

## MVP 范围

MVP 中 Game State Engine 应先支持：

- 比赛阶段粗分。
- 小龙、男爵、防御塔等基础资源背景。
- 击杀和团战结果的重要性判断。
- 简单的死亡时间影响。
- 基础可讲述角度。

MVP 不要求精确建模所有宏观决策，也不要求像职业分析师一样解释复杂运营。第一目标是让 AI 避免机械播报，并能解释明显高价值事件。
