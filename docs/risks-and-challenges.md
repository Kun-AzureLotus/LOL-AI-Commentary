# 风险与挑战

## 总览

英雄联盟AI解说员的主要风险不只是技术实现难度。更大的风险来自信息边界、模型行为、实时体验和产品定位。

如果系统泄露隐藏信息，它会变成作弊工具。如果系统提供操作建议，它会变成 AI 教练。如果系统只机械播报事件，它又无法达到产品目标。

## 信息泄露风险

风险：

系统可能通过 API、视觉识别或错误融合暴露玩家队伍无法合法观察到的信息。

典型场景：

- 推断战争迷雾内敌人位置。
- 根据不可见敌人行为解释局势。
- 把视觉误识别当作确定敌方动向。
- 后续模块绕过 Visibility Filter 读取原始输入。

缓解策略：

- 所有输入必须经过 Visibility Filter。
- 后续模块禁止访问原始 API 和原始 OBS 数据。
- 每条可解说事实必须有来源和可见性标记。
- Prompt Builder 只传递事实白名单。
- 对低置信视觉结果降级或沉默。

## AI 教练化风险

风险：

解说可能从“解释局势”滑向“指导玩家操作”。

典型越界输出：

- “你现在应该去打龙。”
- “赶紧撤退。”
- “从上半区绕过去。”
- “下一波应该抓下。”

缓解策略：

- 产品愿景中明确非目标范围。
- Game State Engine 只解释意义，不输出建议。
- Prompt Builder 明确禁止“你应该”类表达。
- LLM 输出后可增加安全检查。
- 文档和贡献指南明确禁止教练功能。

## 模型幻觉风险

风险：

LLM 可能补充未经确认的事实、夸大事件意义或预测未来。

典型场景：

- 模型声称敌方正在做某个目标。
- 模型预测“一定会结束比赛”。
- 模型把普通击杀描述成决定性事件。

缓解策略：

- LLM 只能接收结构化提示词。
- Prompt Builder 明确区分可引用事实和风格要求。
- 重要事实由结构化模块给出，不交给 LLM 猜。
- 禁止未来预测和隐藏信息推断。
- 输出长度保持短，降低模型发挥空间。

## 实时延迟风险

风险：

解说如果来得太晚，即使内容正确，也会破坏体验。

延迟来源：

- OBS 捕获和视觉识别。
- Riot API 轮询。
- 状态融合和事件判断。
- LLM 响应。
- TTS 生成和播放。

缓解策略：

- 为每条事件设置过期时间。
- Narrative Director 可以丢弃过期事件。
- TTS 支持打断和队列清理。
- MVP 优先短句解说。
- 对高频事件使用规则模板或轻量生成路径。

## OBS 视觉识别风险

风险：

屏幕捕获信息复杂，视觉识别可能不稳定。

影响因素：

- 分辨率。
- UI 缩放。
- 色彩设置。
- 皮肤和技能特效。
- 直播压缩。
- 小地图遮挡。
- 镜头快速移动。

缓解策略：

- 先做受限视觉任务。
- 视觉结果带置信度。
- 与 Riot API 事实交叉验证。
- 低置信度结果不进入关键解说。
- MVP 避免依赖大型全画面理解。

## 事件边界风险

风险：

团战、一打一和资源争夺不是瞬时事件，开始和结束边界可能模糊。

典型问题：

- 团战尚未结束就提前总结。
- 多个小规模战斗被误合并。
- 同一个事件被重复解说。

缓解策略：

- Event Detection 输出事件状态，例如 started、ongoing、resolved。
- Narrative Director 可延迟总结，等待结果明确。
- 使用冷却窗口避免重复播报。
- 事件对象带唯一标识和生命周期。

## 叙事噪音风险

风险：

AI 说得太多会打扰玩家，尤其是在自己打排位时。

缓解策略：

- Narrative Director 负责沉默策略。
- 低价值事件默认不说。
- 高强度操作期间减少长句。
- TTS 层可丢弃排队过久的语音。
- 解说频率和风格应可配置。

## 产品定位滑坡风险

风险：

开源项目长期发展中，贡献者可能加入教练、侦察、自动化或战绩分析功能，导致产品偏离初衷。

缓解策略：

- 文档明确非目标范围。
- 贡献指南明确禁止功能。
- 架构中保留安全边界。
- 对新增数据源和输出能力进行设计评审。
- 将“是否增强竞技优势”作为功能评审问题。

## Riot 政策与合规风险

风险：

项目需要遵守 Riot 相关 API 和游戏政策。即使技术上可行，也不代表产品上可接受。

缓解策略：

- 只使用合法接口和玩家画面。
- 不自动控制游戏。
- 不提供作弊、隐藏信息或操作优势。
- 保持开源透明。
- 在发布前单独审查 Riot 政策和社区规范。

## 隐私风险

风险：

OBS 画面、玩家数据、语音文本或 API key 可能被上传到第三方服务。

缓解策略：

- 本地优先。
- 明确云端 LLM/TTS 会接收哪些数据。
- 默认最小化上传内容。
- 用户 API key 自管。
- 长期支持本地模型和本地 TTS。

## 开源信任风险

风险：

用户需要相信项目没有读取或泄露非法信息，也没有隐藏自动化行为。

缓解策略：

- 架构文档公开。
- 信息边界公开。
- 未来提供回放和审计日志。
- 关键安全模块保持简单可审计。
- 禁止混入自动化操作能力。

## MVP 最大挑战

MVP 的最大挑战是同时做到：

- 说得少。
- 说得准。
- 说得像解说。
- 不越界。
- 不迟到。

这五点比功能数量更重要。
