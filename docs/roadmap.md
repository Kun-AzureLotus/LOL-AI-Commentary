# 开发路线图

## 路线图原则

路线图应优先验证最大风险，而不是优先堆功能。

本项目的最大风险包括：

- 实时输入是否可靠。
- 信息边界是否可控。
- 事件识别是否足够准确。
- AI 解说是否像解说，而不是日志播报或教练。
- TTS 延迟是否可接受。

因此 MVP 应聚焦端到端最小闭环。回放系统、审计日志系统和高级主播功能应放在后续阶段。

## 阶段 0：架构评审

目标：

- 完成产品愿景、系统架构、模块职责、技术栈、路线图、风险挑战和参考仓库分析文档。
- 明确信息合法性边界。
- 明确 Event Detection、Game State Engine、Narrative Director、Prompt Builder 的职责划分。

验收标准：

- 架构文档能解释系统如何避免作弊和教练化。
- MVP 范围清晰。
- 参考仓库只作为架构理念来源，不作为代码来源。

不做事项：

- 不写产品代码。
- 不集成 Riot API。
- 不集成 OBS。

## 阶段 1：输入采集概念验证

目标：

- 验证 Riot 实时客户端 API 可稳定读取结构化数据。
- 验证 OBS 或屏幕捕获链路可以稳定获取玩家画面。
- 验证两类输入的延迟、频率和稳定性。

验收标准：

- 能获取游戏时间、玩家状态、事件数据和基础目标数据。
- 能捕获玩家当前画面或指定区域。
- 能记录输入延迟和失败情况。

不做事项：

- 不生成最终解说。
- 不实现复杂视觉识别。
- 不实现回放系统。

## 阶段 2：合法信息与状态融合

目标：

- 实现 Visibility Filter 的第一版规则。
- 将 API 与 OBS 结果合并为统一状态快照。
- 为每条事实保留来源、时间戳和置信度。

验收标准：

- 后续模块无法绕过 Visibility Filter 访问原始输入。
- 状态快照只包含合法可见信息。
- 视觉结果不会被无条件提升为确定事实。

不做事项：

- 不生成复杂解说。
- 不处理隐藏敌人推断。
- 不提供操作建议。

## 阶段 3：基础事件检测

目标：

- 实现 Event Detection 初版。
- 识别击杀、目标获取、防御塔变化、小规模战斗和团战结果等基础事件。

验收标准：

- 能从状态变化中产出结构化事件。
- 事件包含时间、类型、参与者、结果和置信度。
- Event Detection 不解释事件意义。

不做事项：

- 不在事件模块中加入叙事判断。
- 不直接调用 LLM。

## 阶段 4：Game State Engine MVP

目标：

- 解释基础事件的局势意义。
- 支持比赛阶段、资源状态、死亡时间和推进影响的基础判断。
- 为 Narrative Director 提供结构化重要性和可讲述角度。

验收标准：

- 同样的击杀在不同上下文下能得到不同重要性。
- 能解释小龙、男爵、防御塔和后期阵亡的基础意义。
- 不输出自然语言，也不提供操作建议。

不做事项：

- 不做复杂宏观策略分析。
- 不做隐藏信息推断。

## 阶段 5：Narrative Director 与 Prompt Builder MVP

目标：

- 实现是否发言、优先级、情绪强度和沉默策略的初版规则。
- 实现结构化 Prompt Builder。
- 保证 LLM 只接收经过治理的提示词。

验收标准：

- 普通低价值事件可以被沉默策略过滤。
- 高价值事件能提高发言优先级和情绪强度。
- Prompt Builder 明确包含事实白名单和禁止输出规则。

不做事项：

- 不让 LLM 直接读取游戏状态。
- 不把叙事决策交给 LLM 自行决定。

## 阶段 6：语音解说 MVP

目标：

- 接入 LLM Commentary Generator 和 TTS Output。
- 形成从实时输入到语音输出的完整 MVP 闭环。
- 验证延迟、打断、过期丢弃和语音长度。

验收标准：

- 能对明显高价值事件生成自然语音解说。
- 不输出操作建议。
- 不预测隐藏信息或未来事件。
- 迟到或低价值解说能被丢弃。

不做事项：

- 不追求多语言。
- 不追求复杂人格。
- 不做赛后复盘。

## 阶段 7：主播场景增强

目标：

- 支持更有表现力的主播解说风格。
- 优化 OBS 场景、音量、混音和直播兼容性。
- 支持更丰富的团战总结和资源交换表达。

验收标准：

- 主播场景仍遵守合法信息边界。
- 语音与直播节奏兼容。
- 风格增强不变成操作建议。

## 阶段 8：回放与审计

目标：

- 增加回放系统和审计日志系统。
- 支持复现输入、状态、事件、叙事决策和提示词。
- 支持开源社区审计信息边界。

验收标准：

- 可以复盘某次解说为什么发生。
- 可以检查某次输出是否引用非法信息。
- 可以用历史样本回归测试事件识别和叙事策略。

说明：

该阶段重要，但不属于 MVP。

## 阶段 9：开放源治理

目标：

- 建立贡献指南。
- 明确安全边界和禁止功能。
- 建立测试样本、评审流程和架构决策记录。

验收标准：

- 新贡献者能理解项目不是 AI 教练或作弊工具。
- 涉及信息边界的改动必须经过严格评审。
- 参考仓库借鉴保持在理念层面，不复制具体实现。
